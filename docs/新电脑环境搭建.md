# 新电脑环境搭建

换机器时，「让 AI 重新具备这套能力」不需要重新教，靠三样东西：

| 东西 | 位置 | 作用 |
| --- | --- | --- |
| 规则文件 | `AGENTS.md` | 让 AI 知道环境、路径、发布流程、禁忌 |
| 重建脚本 | `tools\setup-dev-env.ps1` | 一条命令装回工具链与源码 |
| 探针 | `HoverProbe/` | 只读观测插件，排查游戏窗口布局时用 |

## 步骤

### 0. 前置

- 有本地 HTTP 代理（本项目按 `http://127.0.0.1:7897` 写死，端口不同就改脚本 `-Proxy`）。
  没有代理的话 `github.com` 连不上，脚本里的 clone 和下载都会失败。
- Windows 10 1803 以上（自带 `curl.exe`）。
- **脚本不需要预装任何运行时**：PowerShell 5.1、`curl.exe`、`Expand-Archive`、`Get-FileHash` 都是 Windows 自带；脚本只用 5.1 兼容语法，不要求 PowerShell 7。
- 新电脑**可能没有 git**：这时用浏览器在仓库页面点「Download ZIP」，解压到目标目录，再跑脚本即可（脚本会自己装好 MinGit）。
- 允许跑脚本：`powershell -ExecutionPolicy Bypass -File .\tools\setup-dev-env.ps1`（只对本次生效，不改系统设置）。
- Windows 7 / 8.1 不支持：那类系统跑不了 Dalamud，插件开发本身不成立。

### 1. 让工作区落在「当前对话的目录」

推荐做法：**先在目标文件夹里开一个对话**（比如 `D:\插件开发`、`F:\FF14\Harness`，哪个盘都行），然后说一句「一键部署」。AI 会把仓库**直接落到当前目录**，不猜盘符、不替你换盘：

```powershell
# 当前目录为空（首次使用，最常见）
git -c http.proxy=http://127.0.0.1:7897 clone https://github.com/ctdlb/ff14-plugin-workspace.git .
```

`clone` 末尾那个 `.` 就是「落到当前目录」——所以 `D:\插件开发` 开对话就落到 D 盘，`F:\FF14\Harness` 就落到 F 盘，命令一个字都不用改。

工作区本身就是一个仓库（`ctdlb/ff14-plugin-workspace`），克隆完里面就有 `AGENTS.md`、`docs\`、`tools\`。

**工作区目录必须就是 `AGENTS.md` 所在的那一层**：DSH 只从「当前对话目录」加载工作区级规则，不会往下钻子文件夹。所以多套一层（`D:\插件开发\ff14-plugin-workspace\`）又在上层（`D:\插件开发`）开对话时，读不到工作区规则；套了就改在子目录那一层开对话。

**当前目录里已经有别的东西时不要直接 clone**（git 会拒绝，或者把文件挤在一起）。这时先问用户：

- 要「在工作区里新建一个子目录装仓库」→ `git clone … <子目录名>`
- 还是「就地初始化、把仓库内容铺进来」→ 这时要先把已有文件备份，再 clone 到临时目录复制过来（会覆盖同名文件，必须经用户同意）

`-c http.proxy=…` 不能省：`github.com` 直连会超时。上面按 `7897` 写死，端口不同就改；确实没有代理时删掉该参数。

**新机器上还没有 git 时**：用浏览器打开 `https://github.com/ctdlb/ff14-plugin-workspace` → `Code` → `Download ZIP`，把 zip 里的内容解压到当前目录（注意是解压到「当前目录」，不要多套一层文件夹）；脚本装好 MinGit 之后，再在当前目录 `git init` 并关联远端即可。

旧机器还在的话，直接整个目录拷贝最省事（约 5.5 MB，不含工具与知识库）。

插件（`TextToTalkCN` 等）由作者自己按需 clone 或加 `-IncludeMyPlugins`，这个脚本默认不装。

### 2. 跑脚本

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Dir\tools\setup-dev-env.ps1" -Workspace $Dir
```

`-Workspace` 可以省略：脚本默认按自己的位置推断工作区（脚本一定在工作区下的 `tools\` 里），装在哪个盘都对；显式写 `-Workspace $Dir` 效果一样。

它会做六件事，已存在的直接跳过（幂等）：

| 步骤 | 产物 | 体积 |
| --- | --- | --- |
| 装 .NET 10 SDK | `<Root>\dotnet` | 770 MB |
| 装 MinGit | `<Root>\git` | 92 MB |
| 装 EXDViewer 便携版 | `<Root>\EXDViewer` | 77 MB |
| clone 四个知识库 | `<Root>\KnowledgeBase` | 137 MB |

`<Root>` 默认＝工作区所在盘的 `\FF14Dev`（下表里有说明）；**真人在终端里跑时，脚本会先把这一步报给你、让你回车确认或直接输入别的目录**。装的过程中如果根目录建不出来（C 盘根目录没写权限、盘满），会当场问你要不要换目录，最多问三次。

**默认不装任何插件**。这个脚本会给别的玩家用，他们只需要运行环境和知识库；作者自己的插件（`TextToTalkCN`、`DalamudPlugins` 仓库，以及把发行包放进 `devPlugins`）只有加 `-IncludeMyPlugins` 才会做。

只想补其中一部分时用开关：`-SkipDotnet`、`-SkipGit`、`-SkipViewer`、`-SkipKnowledge`、`-SkipRepos`、`-SkipPluginInstall`。

可调参数：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `-Root` | `<工作区所在盘>:\FF14Dev` | 工具与知识库根目录；默认跟工作区同盘，**真人在终端里跑时会先问一句**，直接回车即用它 |
| `-Workspace` | 脚本所在目录的父级（即工作区） | 插件仓库的父目录；搬动工作区后不用改 |
| `-Proxy` | `http://127.0.0.1:7897` | `github.com` 的下载与 clone 走这个代理 |
| `-KnowledgeBaseRoot` | `<Root>\KnowledgeBase` | 知识库放别处时单独指定 |
| `-DevPluginsDir` | 自动探测 XIVLauncherCN 的 `devPlugins` | 插件装到别处时指定 |
| `-SkipViewerInit` | 关 | 跳过 EXDViewer 首次设置（检测游戏目录 + 拉起 GUI） |
| `-SkipViewerLaunch` | 关 | 只检测并打印游戏目录，不弹 EXDViewer 窗口 |
| `-GitHubToken` / `-GitHubUser` | 无 | 直接把令牌存进凭据管理器，之后 push 不弹窗 |
| `-SkipGitHubToken` | 关 | 这次不处理令牌 |
| `-SkipPluginInstall` | 关 | 只准备源码，不装插件本体 |
| `-IncludeMyPlugins` | **关** | 连作者自己的插件一起装（克隆两个插件仓库 + 把 TextToTalkCN 放进 `devPlugins`）；别人用不需要它 |

网络分工（脚本内固定）：`api.github.com`、`dot.net` 直连并绕过系统代理，`github.com` 的下载与 `git clone` 走代理。系统代理开着时，直连 API 反而会被挡成 403，所以不要图省事全走代理。

### 2.5 用户级规则文件：不在本仓库

DSH 每次启动都会读 `%USERPROFILE%\.dsh\AGENTS.md`（记作 `DSH_HOME`）。它**对所有工作区、所有新对话生效**，相当于全局规则。

它的**正本在另一个仓库**：`ctdlb/dsh-plugins` 根目录的 `AGENTS.md`（那个仓库就是用来换机装回 DSH 环境的）。本工作区**不存副本**，`tools\setup-dev-env.ps1` 也**不处理这个文件**——它只装 FF14 插件开发需要的东西，别的玩家部署本工作区时不会多出一个跟他无关的规则文件。

要改用户级规则：

1. 直接改 `C:\Users\<你>\.dsh\AGENTS.md`；
2. 改完同步到 `ctdlb/dsh-plugins` 仓库的 `AGENTS.md`（手动复制或 `git` 提交）；
3. 重开 DSH 生效。

换机时：先跑 `dsh-plugins` 的 `install.ps1` 把 DSH 环境装回来，再处理本工作区。

### 3. 手动收尾

1. 启动一次 `<Root>\EXDViewer\current\viewer.exe`，在「设置」里把游戏目录指到 `...\最终幻想XIV\game`，然后正常关闭。
   这一步不能省：MCP 模式下它只认「GUI 曾经成功加载过」的配置，否则报 `找不到已保存的设置`。
   **脚本已经半自动处理**：装完后它会读 `%APPDATA%\XIVLauncherCN\launcherConfigV3.json` 的 `GamePath`，把 `...\game` 打印出来，并直接启动 EXDViewer；你只要照那一行填、关窗口。已配过的机器会打印「已有配置」并跳过。
   为什么不写死配置：实测伪造 `app.ron`（哪怕只放一行 `exd/root`）也会被判「找不到已保存的设置」，EXDViewer 只认自己 GUI 存出来的完整状态。
2. 验证数据查询：
   ```powershell
   powershell.exe -NoProfile -File "$Dir\tools\exd.ps1" -Tool health_check
   ```
3. 进游戏 `/xlplugins`，按需添加插件库或安装自己要用的插件（本脚本默认不装任何插件）。插件只会装在一处：从插件列表安装的落在 `installedPlugins`，手动放进 `devPlugins` 的落在那边；两处同名会冲突，只用一种。
4. GitHub 令牌：在 Windows 凭据管理器里存一条 target 为 `git:https://<用户名>@github.com` 的令牌，推送才走 HTTPS。
   **也可以让脚本代做**：`-GitHubToken <令牌>`（用户名默认从 origin 推），脚本用 `git credential approve` 写进凭据管理器，之后 push 不再弹窗。令牌得你自己在 GitHub 上生成。
5. 用 AI 客户端打开工作区，让它先读 `AGENTS.md`，再开始干活。装在非默认目录时，告诉它「工作区就是 `$Dir`」，它会按实际路径理解规则文件里的默认路径。全局规则那份（`DSH_HOME\AGENTS.md`）按 2.5 自己决定要不要启用。

## 不随仓库走的东西

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| AI 会话历史 | `%USERPROFILE%\.dsh` | 不上云，会话记录不会跟着仓库走；要保留就整目录拷 |
| 插件配置 | `%APPDATA%\XIVLauncherCN\pluginConfigs` | TextToTalkCN、Jiage 的设置 |
| EXDViewer 配置 | `%APPDATA%\EXDViewer\data\app.ron` | 指向游戏目录、界面状态 |
| Dalamud 开发环境 | `%APPDATA%\XIVLauncherCN\addon\Hooks\dev` | 由 XIVLauncherCN 自己维护，不用备份给你们 |

& '<dev>\dotnet\dotnet.exe' --list-sdks          # 应有 10.0.402

## 常见故障

- **下载 403**：`api.github.com` 走代理反而被挡。脚本对 API 用 `--noproxy *`，对 `github.com` 才用代理；手动排查时注意同样区分。
- **clone 超时**：代理没开或端口不同，改 `-Proxy`。
- **`exd.ps1` 报「找不到已保存的设置」**：先按第 3 步启动一次 GUI。
- **编译报找不到 SDK**：`build.ps1` 会依次找 PATH、`<dev>\dotnet`、`%ProgramFiles%\dotnet`，PATH 里的那个通常没有 SDK，以 `<dev>\dotnet` 为准。
