# 插件开发运行时坑

给「悬停查询 / 原生界面改写」这类插件准备的实测记录。每条都是踩过之后确认的结论，不是推测。

## 1. 物品 ID 有偏移，必须先归一化

游戏传给插件的物品 ID 不是干净的基础 ID：

| 状态 | 偏移 | 例子 |
|---|---|---|
| 普通物品 | 无 | 5214 = 火砂砾 |
| HQ 物品 | +1,000,000 | 1,005,214 |
| **收藏品状态** | **+500,000** | **505,214** |

**坑**：只写 `% 1_000_000` 去掉 HQ 偏移是不够的。收藏品状态下算出来是 `505214`，物品表里没有这一行，于是：

- 查「能否上架」得到 false → 整块价格不显示
- 去查价格接口 → 拿一个不存在的 ID，静默失败

**正确做法**（`Jiage` 的 `PriceTip.cs`）：

```csharp
private const uint HqOffset = 1_000_000;
private const uint CollectableOffset = 500_000;

private static uint NormalizeItemId(ulong rawItemId)
{
    var id = (uint)(rawItemId % HqOffset);
    if (id is >= CollectableOffset and < HqOffset)
        id -= CollectableOffset;
    return id;
}

// 调用处：var itemId = NormalizeItemId(raw); var hoveredHq = raw >= HqOffset;
```

**判据**：悬停收藏品时价格块完全没有 → 先怀疑这里。修好后，收藏品状态的火砂砾能显示基础物品（5214）的市场价。

**注意**：偏移只在「物品处于收藏品状态」时出现。市场里买到的同款物品是普通版本，不带偏移，所以光搜市场测不出来，得用收藏品采集/制作/钓鱼拿到手上再悬停。

## 2. 判断「能不能上架」只看一个字段

```csharp
var item = Service.DataManager.GetExcelSheet<Item>().GetRowOrDefault(itemId);
var marketable = item is not null && item.ItemSearchCategory.RowId != 0;
```

- `ItemSearchCategory == 0` 就是「不可在市场出售」，不管它是不是收藏品、`PriceMid` 填了多少
- 典型误判：活动/兑换用的收藏品（如「缇姨家的塔可饼促销文化衫必需品」，RowId 52025，`ItemSearchCategory=0`）本身没有市场价，悬停不显示才是对的
- Price Insight 用的就是这个规则，跟着用可以保证两边显示一致

**别用 `IsUntradable` 判断**：它管的是能不能交易给玩家，和能不能挂板是两回事。

## 3. Universalis 聚合接口：一次请求拿全部范围

```
GET https://universalis.app/api/v2/aggregated/{worldId}/{itemId1,itemId2,...}
```

- 一次最多 50 个物品（Price Insight 也是这个上限）
- 返回里每个物品已经按 **world / dc / region** 三档给好，不用按范围分别请求
- 国服可用：先 `/api/v2/worlds` 拿世界 ID（龙巢神殿 1166、紫水栈桥 1043、银泪湖 1183），再 `aggregated/1166/4551`，HTTP 200

**DTO 层级容易写错**（写错的表现是一大片 `CS1061`，说 `Aggregate` 里没有 `MinListing`）：

```
AggregatedResponse.Results[]            // 每个物品一项
  └ AggregatedItem { ItemId, Nq, Hq }
      └ AggregateGroup                  // 三档数据在这一层
          ├ MinListing     : Aggregate { World, Dc, Region }
          ├ RecentPurchase : Aggregate { ... }
          ├ AverageSalePrice : Aggregate { ... }
          └ DailySaleVelocity : Aggregate { ... }
              └ Aggregate
                  ├ World  : PriceEntry?  // 含 Price / WorldId / Timestamp / Quantity
                  ├ Dc     : PriceEntry?
                  └ Region : PriceEntry?
```

**注意**：`minListing` 只有价格没有时间戳。要显示「x 天前」就取同范围的 `recentPurchase` 时间兜底，别硬等一个不存在的字段。

## 4. 往物品悬浮窗（ItemDetail）插文字的三条硬经验

| 项 | 做法 |
|---|---|
| 找插入点 | `GetNodeById(2)` 是「提示行」容器、`GetTextNodeById(44)` 是正文基准节点；价格节点自己 `IMemorySpace.GetUISpace()->Create<AtkTextNode>()` 建，NodeId 固定 **32615**（Omni 用 32612，错开防撞） |
| 别加 `TextFlags.AutoAdjustNodeSize` | 加了之后，游戏每次换文本都会按自己的算法重算宽高，把你算好的像素折行结果冲掉。缓存命中时不触发重算，所以只在「按 Alt 强制刷新」或「重载插件」后溢出——这个现象本身就是判据 |
| 超出屏幕下沿 | **撑高多少，就把整个 addon 上移多少**（Price Insight 的 `itemTooltip->SetPosition(X, Y - priceNode->Height)`）：`extra = newHeight - baseHeight; addon->SetPosition(addon->X, 游戏给的Y - extra)`。`addon->Y` 里含自己上一次的位移，所以要先 `+appliedExtraY` 还原成游戏位置再减，否则会越提越高；禁用插件时再 `+appliedExtraY` 还回去 |

**折行宽度别写死**：用 `addon->GetScaledWidth(true) - 18`，固定值（比如 330）会把「（4 天前）」这种短后缀硬拆到下一行。

### 插节点的标准写法（照 Dalamud 自己的 DtrBar）

`<dev>\KnowledgeBase\Dalamud\Dalamud\Game\Gui\Dtr\DtrBar.cs:535-545`（`AddNode`）是 Dalamud 官方往原生 addon 里加文字节点的代码，可以直接当范式：

1. **兄弟链是线性的**：从 `RootNode->ChildNode` 沿 **`PrevSiblingNode`** 一路走到 `null`，那个节点就是链尾（如果是循环链，这个循环会死循环——所以它一定不是）。
2. 新节点接到链尾**之前**：`node->NextSiblingNode = 链尾; 链尾->PrevSiblingNode = node; node->ParentNode = 链尾->ParentNode;`（`node->PrevSiblingNode` 留 `null`）。
3. **`RootNode->ChildCount += 1`**——官方代码明确做了这一步，自己手写挂链时最容易漏。
4. 最后 `addon->UldManager.UpdateDrawNodeList()`。

另外两条同源事实：

- `IMemorySpace.GetUISpace()->Create<T>()` 内部会先 `Memset` 再调 `T.Ctor()`，不用自己调构造函数。
- 想知道节点有没有真的进绘制链表：遍历 `addon->UldManager.NodeList`（长度 `NodeListCount`），找自己的指针；找不到就是没进去。**链表序号＝绘制先后已实测证实（2026-10-24）：编号大的后画、压在上面**，所以节点要挂链头，见第 15.2 节。

## 5. 可兑换物品：原始材料查的是「兑换后」的价格

重建伊修加德 / 天穹街的采集材料本身不能上架，要先交给资源检查员换成「已检查」版本。

- 表：`HWDGathererInspection`，每行一组检查项
- 交进去的物品：`entry.RequiredItem.ValueNullable?.Item.RowId`，鱼类走 `entry.FishParameter.ValueNullable?.Item.RowId`
- 换回来的物品：`entry.ItemReceived.RowId`
- 国服这张表存在（实测 4 行），可以放心做

悬停时若命中映射，就改查目标物品的价，并在标题后标一句「（检查后）」。这个功能在 Price Insight 里还是个没合并的 PR（#59）。

## 6. 原生节点：谁创建谁负责拆，否则会跨版本残留

往游戏 addon 里插自定义节点（`IMemorySpace.GetUISpace()->Create<AtkTextNode>()`）时，节点活在**游戏自己的内存**里，插件卸载不会回收它。

**症状**：改了代码、甚至禁用了插件，悬浮窗里还显示着上一版留下的文字。位置常常是「窗口底部」的旧坐标，所以字会飘在内容中间。

**为什么禁用插件也没用**：节点还挂在 addon 的节点链上，状态是「可见 + 有文字」，游戏每次重画 addon 就一起画出来。只有重启游戏（或 addon 被销毁重建）才会清掉。

**代价**：旧版本的 bug 会「穿越」到新版本，看起来像新 bug，白排查好几轮。

**两道保险**

1. **卸载时拆**：`Dispose` 里先把自己插入的节点从兄弟链上摘掉（前后兄弟互接、`ParentNode` 置空、`UpdateDrawNodeList()`），再清一遍链上同 ID 的遗留节点。
2. **建新节点前清**：`Create` 之前先 `addon->GetNodeById(你的NodeId)`，找到就清空文字、隐藏、摘链，并把 `NodeId = 0` 让下次能找到下一个（否则 `GetNodeById` 永远返回同一个）。

**判断是不是残留**：禁用插件后症状仍在 → 是残留，不是当前代码的问题；重启游戏后症状消失 → 确认是残留。

**加高/减高要记账**：窗口高度加减必须用同一个记账值（`addedHeight`），别用节点当前高度反推，否则多悬停几次会越减越多。

## 7. Universalis 的空对象 = 该品质没有样本，不是查询失败

聚合接口里每个物品按品质分 `nq` / `hq` 两组，每组四个统计字段。**字段值是空对象 `{}` 时表示「没有样本」**，不是报错，也不是 0。

实测 `aggregated/1166/5214`（火砂砾，收藏品）：

```
nq.minListing.region      { price: 222, worldId: 1174 }
nq.recentPurchase.region  { price: 2, timestamp: 1788371883000 }   // 毫秒
nq.averageSalePrice       {}                                       // 空
nq.dailySaleVelocity      {}                                       // 空
```

同一次请求 `49245`（炖剑山芋）的 HQ 组则有数据：`averageSalePrice.region.price = 5633.87`、`dailySaleVelocity.region.quantity = 452.44`；它的 NQ 组两个字段同样是空。

**原因**：这两个统计量按「近期成交窗口」算，冷门物品（收藏品、老旧装备、活动道具）没人真的成交，窗口里没有样本，接口返回空对象而不是 0。

**实现上要区分三种情况**，不能混：

| 情况 | 判据 | 界面表现 |
|---|---|---|
| 有数据 | 字段存在且有 `price` / `quantity` | 正常显示数字 |
| 没样本 | 字段是空对象 `{}` | 不显示这一行 |
| 请求失败 | HTTP 非 2xx / 超时 | 报错，不要当成「没样本」 |

**坑**：`price` 可能是小数（`5633.8766954377315`），按 `uint` 解析会失败被静默跳过；`quantity` 也是浮点。统一用 `double` 读、显示时再取整。

**给用户的兜底**：均价与销量都没样本时，补一行灰字「（该物品近期无成交记录）」，否则用户会以为插件没查。灰字用 `UIForegroundPayload(20)`。

## 8. 把内容挂到 ItemDetail「最后一行」下面，而不是窗口底部

> ⚠️ **已否决（2026-10-23）**：本节第 5 步「长高窗口」与当前红线冲突 —— 现在的做法是**不动蓝色框（窗口高度、背景、提示行）**，只往 `GetNodeById(2)` 之前插节点，靠节点自己定位。本节保留的原因：后半段「不要做的事」是不可复现的实战教训（改坏原文字只能重启游戏），删掉一定会重踩。若要按本节长高，先确认红线是否已变。

**症状**：按 `窗口高度 - 10` 算 Y，价格块会压住「收购价格：」那行；换到条目少的物品窗口被游戏改小，位置又开始漂；只拉窗口高度，蓝色背景不跟着长。

**可行做法**

1. **找锚点**：扫 `addon->UldManager.NodeList`，取「`Type == NodeType.Text`、`Height > 0`、`Y < 提示行容器 Y`」里 **Y 最大**的那个节点 = 视觉上最后一行（收购价格 / 工匠名 / 商店售价都适用，不依赖道具类型）。
2. **建自己的节点**：`IMemorySpace.GetUISpace()->Create<AtkTextNode>()`，颜色、字号、行距、宽度全部自己设（照抄正文节点 `GetTextNodeById(44)` 的配色即可，别抄工匠名那行）。
3. **定位**：`X = 最后一行->X`、`Y = 最后一行->Y + max(最后一行->Height, 18) + 6`。
4. **挂链**：插在提示行容器（`GetNodeById(2)`）之前，`ParentNode = 容器->ParentNode`，然后 `UldManager.UpdateDrawNodeList()`。
5. **长高**：`WindowNode->SetHeight(原高 + 块高 + 8)`，同步 `WindowNode->AtkResNode` 与 `Component->UldManager.SearchNodeById(2)` 两处高度；提示行容器 `SetYFloat(Y + 增量)`。
6. **还原**：记住增量，`Hide` 时把两处高度减回去、提示行移回，再把节点从链上摘掉。

**不要做的事**

- **不要** `SetText` 注入到游戏自己的文本节点里（看着最优雅，实际会：继承那一行的颜色/字号；单行节点被打开 `MultiLine` 后按它自己的窄宽度折行，把「工匠名」挤成竖排；只还原文字不还原 `TextFlags`/`Width`/`LineSpacing` 会把那一行永久改坏，只能重启游戏）。
- **不要**改 `addon->RootNode` 的高度：它会连带重画标题栏边框，表现为标题栏下面多出一条分隔线。
- **不要**只改 `RootNode->PrevSiblingNode`：国服这版真正控制可见面板的是组件里 id=2 的容器，不改它背景不长。

**参考**：`Caraxi/SimpleTweaksPlugin` 的 `Tweaks/Tooltips/AdditionalItemInfo.cs`（只改 id=2 容器高度、`Y = 窗口高 - 10`、不改 RootNode）。`AtmoOmen/OmenTools` 的 `TooltipManager.cs` 是更彻底的写法（改文本 + `AddonItemDetail::UpdateGroupPositions` 让游戏自己重排），但需要更新版 FFXIVClientStructs，Dalamud 15.0.3.9 自带的结构库里没有这些成员。

## 9. 道具简介框自适应：撑高别人的窗口 = 撑高 + 上移

> 术语约定（用户 2026-10-23 命名，同日更正为「道具简介框」）：这套「往游戏自带 addon 里加内容、撑高窗口、并把窗口上移以免被屏幕裁掉」的做法，统一叫 **道具简介框自适应**（最早写作「道具栏界面自适应」，指同一件事）。以后提这个名字就是指本节。
>
> 容易混的两个词：**道具栏**＝背包那个大窗口（物品格子列表）；**道具简介框**＝鼠标悬停某件物品时弹出的那个小窗（`ItemDetail`）。本节说的是后者。

往游戏自带的 addon（`ItemDetail` 之类）里加内容、把窗口撑高时，**长高的部分永远朝下长**。靠近屏幕下沿悬停时，多出来的那块就会被屏幕裁掉——2026-10-23 实测：价格块一半出屏，看着像“没画出来”。

**做法**（Price Insight `ItemPriceTooltip.cs` 同款）：

```csharp
var extra = (short)(newHeight - baseHeight);     // 这一帧比原版高多少
if (extra != appliedExtraY)                      // 只在变化时挪，避免每帧写位置
{
    var gameY = (short)(addon->Y + appliedExtraY); // 先把上一次的位移还原掉
    addon->SetPosition(addon->X, (short)(gameY - extra));
    appliedExtraY = extra;
}
```

三条判据：

- **必须用「游戏给的 Y」当基准**：`addon->Y` 里已经含着自己上一次的位移，不回加 `appliedExtraY` 就会一帧比一帧高，最后飞出屏幕。
- **关插件时还回去**：`SetPosition(X, Y + appliedExtraY)`，否则会话里会留着被挪高的位置。
- **别在 `PostRequestedUpdate` 里设高度**（会被游戏布局覆盖）；高度放在 `PostUpdate`，位移跟高度同一处设置，顺序不能反。



## 10. 排错纪律：同一类实验没跑完，不要换方向

**踩过的坑（2026-10-23 凌晨）**：想让游戏自己把物品悬浮窗的蓝框撑高，我列出了三条实验：

1. `AtkUnitBase.SetSizeFromConfig(w, h)`
2. `AtkUnitBase.OnRefresh(0, null)`
3. 把「最后一行节点」加高后再 `OnRefresh`

实验 1 没效果，我直接给出「游戏不会替我们算尺寸」的结论，并把「换呈现方式（独立小窗 / `/jg 物品名`）」排到最后、还建议先回去手写高度。

**实际结果**：实验 3 **有效**——加高节点 + `OnRefresh`，游戏真的会重算窗口高度。结论在第三个实验里，而我在第一个实验失败后就下了判断。

**教训**：

- 同一类实验（同一入口族、同一现象假设）要**全部跑完**再下结论，因为它们往往只是「参数/顺序不同」；
- 失败一次得出的只能是「这条路径不通」，不能推成「这个方向不通」；
- 换方向之前要先说明「还有哪些同类实验没做」，并优先把它们补齐；
- 别在用户还有未验证的选项时，把某个选项说成「不推荐」——那是替用户做决定。

**可复用的判断**：如果一个现象只可能由「A 或 B 或 C」三个入口触发，且每个入口的验证成本都在几分钟内，那就三个都测，不要用第一次失败去推断后两个。

## 11. 「不要动原版」要先问清是动哪一层

需求里出现「不要动原版」「保持原生」这类说法时，**「动」有很多层**，不同的人默认的范围不一样，必须先确认：

| 层 | 具体行为 | 常被默认算不算「动」 |
| --- | --- | --- |
| 视觉层 | 改窗口高度、拉伸背景、移动提示行 | 大多数人第一反应会算「动」 |
| 结构层 | 往节点链里塞新节点、改节点属性（宽度 / 标志位 / 坐标） | 部分人算、部分人只把它当「加东西」 |
| 文字层 | 往游戏已有的文字节点里追加/改写文字 | **最容易被忽略**：从外部看「只是多了一行字」，但本质是改动了游戏自己画的文本 |

这三层只是**最常见**的举例，不是穷举。实际还会遇到：音效与提示、配置与存档、日志输出、游戏状态/内存、与其他插件的交互等。所以不要用自己想到的几种当完整清单——要么逐条列出打算做的动作让用户确认，要么直接问「哪些行为绝对不能发生」。

2026-10-23 的 Jiage 就是踩在这条上：我先把它理解成「不动蓝框」，于是做了「只改文字」的版本；用户的原意是**连框里的文字也不能碰**，所以那一版仍然算动过。事后重新确认才对齐。

**可复用的做法**：

- 用户说「不要动 X」时，先回一句「是指视觉、结构、文字三层都不动，还是只不动其中一部分？」，再动手；
- 反过来，如果我们的做法只能落在某一层，先说清「这会改到 X 层的 Y」，让用户决定，而不是自己假定「这么小改动应该没事」；
- 只有「我们自己画窗口、完全不碰游戏节点」才真正落在三层之外。

## 12. 回滚点：标签要标注能力边界，不能只写 `good`

**做法**（Jiage 从 2026-10-22 起坚持的）：用户说「这版可以」时立刻做三件事——`git commit` → 打 `good-YYYYMMDD-HHMM` 标签 → 把 `bin\Release` 整个打包进 `.tmp\archive\Jiage-<版本>-<时间>.zip`。标签和离线包**一一对应**，纯二进制回滚不用编译。

**坑：只写 `good` 不够，必须记这版「碰没碰游戏」**。Jiage 的 6 个标签里有三个坑：

| 标签 | 表面 | 实际 |
|---|---|---|
| `good-20261023-0030` | 效果最像目标 | 独立节点 + 手动拉高窗口，碰蓝框；随后两次卡死 |
| `good-20261023-0105` | 能看见价格、改名「不碰原版属性」 | 仍是把文字 `SetText` 写进游戏自己的节点（文字层），事后被否决 |
| `good-20261023-0837` | 完全没有显示功能 | 才是唯一的安全底座：全文件 0 处界面写操作 |

**结论**：回滚点要带「能力边界」而不是只带版本号。建议的记录格式：

```
标签 / 提交 / 一句话机制 / 已知问题 / 对应的离线包名
```

**附加一条**：本地仓库（无远端，如 Jiage）更要打标签 + 存离线包——换机器时源码和 `.tmp` 都不跟着走，只有离线包能直接救急；但「源码怎么写」这条信息只能靠标签留在 git 里。

## 13. 对照实验必须平行：叠加一次，整段结论作废

**实例**（2026-10-24 凌晨，PriceInsight CN 修「切物品时 Ctrl 提示行残影」）：我提了 A（切物品时先藏提示行）、B（先摆好框、价签晚两帧显示）、C（有缓存时不还原原生高度）三个方案，用户要求按 A→B→C 顺序试。

我做成了这样：

```
A（叠在干净基线上）→ 测：「不行」
B（叠在 A 上）      → 测：「不行」
C（叠在 A+B 上）    → 测：「不行」
```

用户当场指出问题：「那你在 A 有问题的情况下做 B，这样 B 肯定会不准啊」。按红线的做法重做后，**B 在干净基线上一次就正常**——也就是说前面那两轮全白测，而且 C 至今是「未验证」，不是「不行」。

**为什么代价大**：否定的结论会被记成「这条路不通」。一旦记录错了，以后就不会再回头试——**被误判掉的那个方案里，可能正好是正解**。

**正确做法**：

| 要点 | 做法 |
|---|---|
| 基线 | 每个方案都从同一个干净标签（或干净 commit）出发 |
| 分支 | 一个方案一条 `exp/xxx-a`、`exp/xxx-b`…，`main` 永远停在干净标签上 |
| 记录 | 基线标签、改了哪个文件、`git diff --stat` 行数、部署产物大小与时间、用户判定 |
| 结论 | 只有「干净基线上单独测过」才算数；叠加测出来的一律标「未验证」 |

**自查**：给用户报「X 不行」之前先问自己一句——「这个 X 是单独测的吗，还是叠在别的改动上测的？」答不上来就先别下结论。


## 14. 探针必须是独立的第三方插件

**现象**：为了看清某个 addon 的布局，在正在测试（或正在开发）的插件里加一段"只读日志"，然后拿这个版本去跟用户确认效果。探针一旦和业务代码共处一个插件，它就不再是"旁观者"。

**为什么错**：

- 只要探针和被改的逻辑在同一个插件里，你就已经**改了这个插件**：它多注册了监听器、多读了几次节点，时序和开销都变了；更糟的是探针常常顺手改了判断分支（比如早退、跳过某帧），测的就不是原版了。
- 结论会被污染：看起来"这版不行"，其实是"这版 + 探针不行"，而探针不会出现在后续版本里。

**正确做法**：

| 要点 | 做法 |
|---|---|
| 位置 | 探针做成**独立的第三方插件**（单独目录、单独 csproj），只读：不 `SetHeight`、不 `SetPosition`、不建节点；**任何业务插件里都不写探针代码**（无论它在"测"还是"做"） |
| 用途 | 它只负责在几个时间点（`PreRequestedUpdate` / `PostRequestedUpdate` / `PostUpdate` / `PreDraw`）打一行值 |
| 开关 | 自带命令（如 `/hoverprobe`）随时开关，默认开、日志走 `Log.Warning` |
| 组合 | 测 A 插件时：A 开、探针开、其它干扰源开；被测插件的代码里一个字都不加 |
| 两类证据 | ① **事件帧**（`PreRequestedUpdate` / `PostRequestedUpdate` / `PostUpdate` / `PreDraw` 各打一行）看「排版发生在哪一步」；② **每帧采样**（`Framework.Update` 里比对上一帧，只在变化时打）看「稳定期间还有没有人在写」。两类一起看才能区分「写一次就不动」和「每帧都在改」 |
| 安装 | 探针插件由用户自己加进本地插件列表，不混进被测工程 |


## 15. 往游戏 tooltip 里插自绘文字的完整配方

> 来源：Jiage 与 PriceInsight-CN 的实证（2026-10-23～24）。无论哪个插件，只要「往游戏自带窗口里加一块自己画的文字并让窗口变高」，都按这套做。

### 15.1 撑高窗口：三处一起改，时机只能是 `PostUpdate`

| 要改的地方 | 为什么 |
|---|---|
| `WindowNode`（`addon->WindowNode->AtkResNode`） | 窗口本身的高度 |
| 组件里的**九宫格背景**（`WindowNode->Component->GetNodeById(2)`，按 `NodeType.NineGrid` 找更稳） | **只改 `WindowNode` 时背景不跟着长，文字会露在框外**——最容易漏的一条 |
| 组件 `RootNode`、它的 `PrevSiblingNode`、addon 的 `RootNode` | 它们的 `Height` 也参与布局，不同步会出现「字在框里、框不算高」 |

**时机**：写高度必须放在 `PostUpdate`（或 `PreDraw` 也行，但要在游戏重算之后）。

- 放在 `PostRequestedUpdate` / `PreRequestedUpdate` → 游戏随后自己重算，把值覆盖掉。判据：日志里「设 407 → 下一帧读回 340」。
- 放在 `PostUpdate` → 值能守到绘制（实测 `base=272 → 339` 稳定）。

### 15.2 新节点挂链**头**，不是链尾

- 绘制名单里**编号大的后画、压在上面**（已实测，不再是推测）：挂链尾拿到小编号，会被半透明面板盖住（`index=2 < windowIndex=4` 时看不见）；挂链头拿到最大编号，正常显示在最上层。
- 挂链头写法照 `DtrBar.cs:535-545`：从 `RootNode->ChildNode` 沿 `PrevSiblingNode` 走到链头，插在它前面，`ChildCount += 1`，最后 `UldManager.UpdateDrawNodeList()`。
- **反面案例**：插到 `GetNodeById(2)`（提示行容器）**之前**会破坏链——`NodeListCount` 从 117 掉到 2，整个提示框不显示。别照「插在提示行前面」这个直觉做。

### 15.3 文字颜色 / 图标：四个固定值

| 用途 | 写法 |
|---|---|
| 恢复默认色 | `UIForegroundPayload(0)`（`SeStringBuilder.AddUiForegroundOff()`）；**不要用 21** |
| 价格高亮色 | 色号 **506**（金色） |
| 跨服/世界图标 | `BitmapFontIcon.CrossWorld` = **88** |
| 金币符号 / HQ 标记 | `U+E049` / `U+E03C`（游戏自带字形） |

**不要手写 2 字节色号载荷**：`SeString.Encode()` 返回的已是完整字节，再补 `\0` 会让游戏越界崩溃（`C0000005`，栈里指向自己的 `SyncText`）。用 `SeStringBuilder` 的 `AddUiForeground`。

### 15.4 提示行（`NodeId 2`）别挪走，只压住它下沿

原版的「Ctrl键 … Alt键 …」本来**露在框外**；把框底压到它下面约 40% 就是原版观感。把它挪到框内任何位置都会「和原版不一样」。

### 15.5 切物品那一帧：`HoveredItem` 会瞬间为 0

此时**不要清文字、不要还原高度**，否则会闪一帧「空框」或「价格跳一下」。保持上一帧的内容，等新物品的数据到了再换。

### 15.6 和别的插件抢同一个窗口

别的插件（同类的价格提示、整合包）也会改同一个 addon 的高度。我们能做的只有两件事：

1. 自己的写入放在最靠后的时机（`PostUpdate` 之后、绘制之前）；
2. 每次换物品时按「记录下来的正确值」还原，而不是按「当前值」加减——后者会把别人改坏的值当基准，越算越偏。

真正能根治的只有「在游戏排版之前就把内容准备好」（参照实现就是这么做的：它出现的第一帧就已经是最终高度）。

### 15.7 撑高后还是会被改回去：改成「锁定」

如果 `PostUpdate` 写一次仍会在一部分物品上失效（典型：另一个插件注册得比你晚，它的 `PreDraw` 在你之后执行），就把写法从「算差量」改成「**锁目标值**」：

1. 排版那一刻算一次目标值（`lockHeight` / `lockPriceY` / `lockHintY`），记下属于哪件物品；
2. 在 `PostUpdate` **和** `PreDraw` 各挂一次校验：只要读到的值和目标值不一致就写回去（节流，不要每帧刷日志）；
3. 换物品时用记录的**旧目标值**精确还原成原生高，而不是拿当前值反推。

判据：连续切 10 件以上物品，框高与提示行位置不漂移；「永远卡在加载中但日志无报错」则先查后台线程是否静默死了（异常没 catch）。
