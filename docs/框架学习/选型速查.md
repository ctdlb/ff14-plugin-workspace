# 框架选型速查（按「要做什么」查，不是按库查）

> 建立于 2026-10-25（三代目）。这是 `docs\框架学习\` 的**入口**：先看这张表找到「该用谁」，再看对应笔记的 `文件:行号`。
> 所有结论来自本机实读源码；没验证的标「推测 / 未核实」。

## 一、三条基本判断

1. **没有一个库是全能的**。生态里这四层互不替代：原生 UI（ATK）、ImGui 自绘、游戏数据、通用脚手架。选错层，写多少行都没用。
2. **能抄代码的只有 MIT / Apache-2.0**：KamiToolKit、OmenTools、ECommons、CkCommons（MIT）+ OtterGui（Apache-2.0）。GPL / AGPL / 无许可的四个**只能读思路、自己重写**。
3. **能整仓引入的只有 2 个**：`KamiToolKit`（MIT，原生 UI）与 `ECommons`（MIT，脚手架）。其余要么太重、要么工程引用会撞我们的 SDK 约束、要么许可不允许。

## 二、按任务选型

### A. 改游戏自带的窗口（ATK 原生界面）

| 你要做的事 | 用什么 | 出处 / 代价 |
| --- | --- | --- |
| 往别人的 addon 里**插自己的节点** | **KamiToolKit**：`AddonController` 绑 addon + `TextNode` + `AttachNode((AtkUnitBase*)addon)` | `BaseTypes/NodeBase/NodeBase.Linking.cs:31-43`；绘制名单自动重建。**11 个库里唯一能干这个的** |
| 插节点但不想引库 | 手写：`IMemorySpace.GetUISpace()->Create<AtkTextNode>()` + 挂链头 + `UldManager.UpdateDrawNodeList()` | 写法照 Dalamud `Game/Gui/Dtr/DtrBar.cs:520-551`；坑多，见 `docs\插件开发坑.md` 第 15 节 |
| 改窗口里的**文字**（不加节点） | OmenTools `TooltipManager.RegItem`（`StringArrayData[27]`）或 CriticalCommonLib `TooltipService` | `OmenTools\...\Tooltip\TooltipManager.cs:110`；改了要 `TriggerItemDetailUpdate()` 才会重排 |
| 让窗口**自己重新排版 / 撑高** | 调游戏自己的重排函数：`AddonItemDetail.UpdateGroupPositions(NumberArrayData*, StringArrayData*)` | `FFXIVClientStructs\...\Client\UI\AddonItemDetail.cs:136`；原理见 `OmenTools.md` 的「原生重排链」 |

### D. 生命周期与坑（选型之后再读）

| 场景 | 规则 | 出处 |
| --- | --- | --- |
| 任何库的静态服务 | **初始化之后才能调它的东西**，早调就是 NRE | 我们实测过：`DalamudPluginInterface.GetService` 里 NRE |
| 禁用再启用（热重载） | 上一次的异步 `Uninit` 没跑完就 `Init` 会抓到正在拆的容器 → 等它 | 我们在 OmenTools 上踩过，`ThanksGen2\OmenBootstrap.cs` 已加 `pendingUninit` 等待 |
| 游戏退出 | 框架卸载阶段**不要再碰原生内存**（`IFramework.IsFrameworkUnloading`） | 我们踩过 `C0000005`，栈在 `GlobalFrameworkDestroyDetour` |
| 引别人的库 | **不用 `ProjectReference`**（两套 SDK 属性互污染），用编好的 dll 或 NuGet | 本工作区已定 |
| KTK 的隐藏依赖 | KTK 自己不调 `ExpansionInterop.Initialize`，要靠 OmenTools `DService.InitAsync` 里那一步 | `OmenTools\DService.cs:56` |
| 会改全局日志等级的库 | ECommons（`Init` 设 Verbose）、CkCommons（设 Debug） | 会污染宿主插件日志，注意 |

## 三、三个「组合配方」

1. **改游戏原生窗口（最常见）**：`KamiToolKit` 插节点 + 游戏自己的 `Generate*/UpdateGroupPositions` 重排 + `ECommons` 的节流/任务。三个都是 MIT。
2. **纯 ImGui 插件（不想碰原生）**：`Dalamud` 自带 ImGui + `ECommons.ImGuiEx` 补控件 + OtterGui 抄 `Table`/`SaveService`。零原生内存风险。
3. **数据类插件（背包/价格/制作）**：`ECommons` 查表 + 自己写 Universalis 客户端；**不要**为了省事引 CriticalCommonLib（GPL + 初始化极重）。

## 四、明确不要的

| 库 | 为什么不要 |
| --- | --- |
| Luna | AGPL-3.0（抄即传染）+ `ImSharp` 子模块是 SSH 空目录，本机编不过 + 强制换 ImGui 绑定 |
| pictomancy | AGPL-3.0 + 层级不对（世界空间 3D vs ATK 节点树） |
| CriticalCommonLib | GPL（抄即传染）+ 一条签名拖 20k 行数据层 |
| ImComponents | GPL-3.0 + 只认 `XIVLauncher` 路径，国服编不过 |
| Reatkact | **无 LICENSE** + 作者自己写「please don't actually use this」 |
| OmenTools.KamiToolKit | MIT 但必须与 KTK、OmenTools 三者同解决方案（撞我们的 SDK 约束）；它做的事我们按需抄 10 行即可 |
| CkCommons | MIT 但 19k 行只为省样板；唯一想留的是那个 `IsAddonReady` 判定（照抄） |
