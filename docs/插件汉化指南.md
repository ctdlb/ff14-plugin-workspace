# 给卫月插件做汉化：能复用的结论

来源是 2026-10 做 Sonar CN（简繁双语）和 TextToTalkCN 时验证过的东西。目标：下次拿到一个第三方插件，知道该走哪条路、坑在哪。

## 一、先判断这插件能不能汉化

| 情况 | 判断方法 | 结论 |
|---|---|---|
| 用了 i18n 框架 | 源码里搜 `EnumLoc`、`CheapLoc`、`Localize`、`resources` | 最好，直接加语言包 |
| 文本集中在资源文件 | 有 `.resx` / `.json` / `.xml` 语言文件 | 好，替换或补充资源 |
| 文本写死在代码里 | 到处是 `ImGui.Text("English")` | 只能改代码，工作量大且会随上游更新不断冲突 |
| 闭源 | 只有 DLL | 只能做运行期注入（反射），或者放弃 |

## 二、Sonar 用的是哪套（AG.EnumLocalization + CheapLoc）

### 键的拼法（最容易搞错）

键 = **模块名 + `.` + 特性里的键**。模块名来自枚举上的 `[EnumLocStrings("Module")]`；如果不带参数，模块名取**枚举类型名**。

```csharp
[EnumLocStrings("ConfigWindow")]
public enum ConfigWindowLoc
{
    [EnumLoc("Tab.General", "General")] General,   // 键 = ConfigWindow.Tab.General
    [EnumLoc(Fallback = "Data Center")] Datacenter, // 键 = ConfigWindow.Datacenter，文本 = Data Center
    Advanced,                                        // 无特性：键 = ConfigWindow.Advanced，文本 = Advanced
}
```

三种写法语义不同，别混：

| 写法 | 键 | 后备文本 |
|---|---|---|
| `[EnumLoc("Tab.General", "General")]` | `模块.Tab.General` | `General` |
| `[EnumLoc("Tab.General")]` | `模块.Tab.General` | 无（回落到键名） |
| `[EnumLoc(Fallback = "General")]` | `模块.成员名` | `General` |
| 无特性 | `模块.成员名` | 成员名 |

### 语言包格式

`Resources/<语言码>.<模块>.lang.json`，扁平字典：

```json
{
  "__Meta.Author": "ctdlb",
  "__Meta.Language": "简体中文",
  "ConfigWindow.Tab.General": "通用",
  "ConfigWindow.Datacenter": "大区"
}
```

必须在 csproj 里登记成嵌入资源，否则运行期读不到：

```xml
<EmbeddedResource Include="Resources\cn.plugin.lang.json" />
```

### 让插件默认就用中文

官方代码的预设是「跟随游戏数据语言」，中文用户首次启动仍是英文。两种做法：

- **改代码**：在 IoC 初始化里判断语言配置为空时，写入资源名并保存（我们 fork 版的做法）
- **不改代码**：让用户手动去「语言设置 → 预设」选一次

### CheapLoc 是另一套，格式不同

上游大量使用 `Loc.Localize("Key", "Fallback")`。它的语言包格式是**对象数组**，不是扁平字典：

```json
{
  "AboutBroughtBy": { "Message": "由 Sonar 团队为您带来", "Description": "" }
}
```

塞扁平字典进去会报：

```
Newtonsoft.Json.JsonSerializationException: Error converting value "..." to type 'CheapLoc.LocEntry'
```

### 中文数据表可能缺条目

如果插件的游戏数据表有「繁体中文」列但覆盖不全，选繁体时缺的条目会回落到数据表原始语言（日文）。稳妥做法：**界面语言包用繁体，游戏数据统一走简体**，在读取语言的地方把 `ChineseTraditional` 映射成 `ChineseSimplified`。

## 三、写死在特性里的文本（TextToTalkCN 踩到）

有些界面文字不写在 `ImGui.Text(...)` 里，而是放在特性参数里，再由源生成器画到界面：

```csharp
[Tooltip("Set specific voice presets to be used for Ungendered, Male, and Female characters.")]
public bool UseGenderedVoicePresets { get; set; }
```

生成器里直接内插了原文，所以无论语言包加多少条都不会生效：

```csharp
ImGui.Text(@"{{option.Tooltip}}");   // 永远是英文
```

**查法**：搜生成器源码里的特性取值（如 `option.Tooltip`），再看它是不是直接内插；同时把 `[Tooltip(`、`[Label(`、`[Description(` 都搜一遍。

**修法**：生成器改成按配置项名去查表，翻译表补同名键：

```csharp
ImGui.Text(global::TextToTalk.Resources.Strings.Get("ConfigTooltip" + option.Name));
```

```
Strings.resx            → ConfigTooltipUseGenderedVoicePresets = Set specific voice presets...
Strings.zh-Hans.resx    → ConfigTooltipUseGenderedVoicePresets = 为无性别、男性、女性角色分别指定要使用的语音预设。
```

### 只补中英两套就够

`ResourceManager` 查不到某个语言的键时，会回落到中性资源（通常是 `Strings.resx` 的英文），不会显示空白或 `[Key]`。所以其他语言的 resx 不用动。

### 验证汉化真的进包了

编译通过不代表文本进包。两个实测有效的检查：

| 查什么 | 怎么查 |
|---|---|
| 代码里的键名 | 按 **UTF-16** 读 DLL 字节找键名，例如 `ConfigTooltipUseGenderedVoicePresets` |
| 翻译表里的中文 | 按 **UTF-8** 读卫星程序集 `zh-Hans\<程序集名>.resources.dll` 找中文原文 |

键名是 C# 字符串字面量（UTF-16），而资源文件里的字符串按 UTF-8 存，混着搜会漏。

## 四、要能用上游更新，内部名必须独立

Dalamud 判断「这个插件是不是同一个」用的是 `InternalName`，判断「要不要覆盖」用的是版本号。源码在 `Dalamud/Plugin/Internal/PluginManager.cs`：

```csharp
plugin.Manifest.InternalName == remoteManifest.InternalName                    // 同一个插件
InstalledFromUrl == remoteManifest.SourceRepo.PluginMasterUrl || !IsThirdParty // 官方库来源
candidateVersion > installedVersion                                             // 版本更高才覆盖
```

**结论**：汉化版如果沿用上游的 `InternalName`，只要版本号低于上游就会被上游覆盖掉。所以：

1. 改 `AssemblyName`（打包器从程序集名推 `InternalName`，只改 manifest 字段无效）
2. manifest 文件名也要跟着改（打包器找 `$(AssemblyName).json`）
3. 版本号自己维护，必要时比上游高

代价：和官方版不能同时启用（命令重名、配置目录不同）。要在两个版本间切换，让用户只启用一个。

## 五、发布前过一遍

- [ ] `AssemblyVersion` 和 `pluginmaster.json` 里的版本一致
- [ ] `InternalName` 与上游不同，不会互相覆盖
- [ ] 语言包都登记进 csproj 且打进 zip（解压后能在 `Resources` 里找到）
- [ ] 包体不含 `.pdb`、其他平台的 native 库
- [ ] 第三方依赖的许可证文件没被打包器丢掉
- [ ] **插件仓库 README 里的 Release 版本号**（如 `Releases · v1.43.15-cn`）跟着改——它只是文字标签，链接照常能用，所以最容易漏，TextToTalkCN 已经漏过两次
- [ ] 上游许可证允许分发衍生版本（Sonar 是 Proprietary，所以只做本地/私有，公开前先联系作者）

**一劳永逸的写法**：README 里不写具体版本，直接写「下载最新打包」并链到 releases 页，以后发版就不用再改文档。

## 六、许可与合规（真踩过）

`Proprietary. All rights reserved.` 的插件，改代码 + 打包程序集 + 公开分发，三样占全了就是侵权。可行的低风险顺序：

1. 只做**语言包**，交给上游合并（最干净，还能长期维护）
2. 提 PR 给上游，等合并
3. 本地自用，不公开
4. 公开分发改过的构建（风险最高：DMCA 下架 → 服务端识别 → 理论上还有诉讼）

**服务端能识别非官方客户端**：握手包里带 `SecretMetaBytes`，官方 CI 构建时有密钥、自编版为空；再配合 `FlavorUtils` 解析内部名、`HardwareIdentifier` 稳定指纹，判定成本很低。改内部名并不能躲掉「不是官方构建」这个事实。
